What each metric means

Tell backend to use these definitions consistently:

Identity / context

player: player name

team: team abbreviation

games: games played

rush_attempts: total rushing attempts

Efficiency

epa_per_rush: expected points added per rushing attempt

success_rate: successful rushes / rush attempts

yards_per_attempt: rushing yards / rushing attempts

yards_per_touch: (rushing yards + receiving yards) / (rush attempts + receptions)

fpoe: season-to-date fantasy points over expectation

Explosiveness

explosive_run_pct: runs of 10+ yards / rush attempts

breakaway_run_pct: preferred definition = runs of 15+ yards / rush attempts

breakaway_runs: total runs of 15+ yards

longest_run: longest rushing gain

Elusiveness / independent rushing skill

broken_tackles: total broken tackles on rushes

broken_tackles_per_att: broken tackles / rush attempts

yac_per_att: rushing yards after contact / rush attempts

ybc_per_att: rushing yards before contact / rush attempts

Composite

runner_score: 0–100 composite “how good is this RB as a runner” score

Runner Score formula

Tell backend to calculate percentiles across RBs only, then scale to 0–100.

Use:

Runner Score =
(EPA / Rush percentile * 0.25)
+ (Success % percentile * 0.20)
+ (Yds / Att percentile * 0.15)
+ (Explosive % percentile * 0.15)
+ (Broken Tackles / Att percentile * 0.15)
+ (YAC / Att percentile * 0.10)

That gives a balanced score across:

efficiency

consistency

explosiveness

tackle-breaking

Data rules for backend

Tell them:

RBs only

One row per player

Use season-to-date data

Return null for missing values, not empty strings

Round percentages and rate stats to 2 decimals

Counting stats should stay integers

runner_score should be rounded to 1 or 2 decimals

Default sort should be:

runner_score descending, or

epa_per_rush descending if you want a purer efficiency sort

Include a minimum sample filter if needed for ranking integrity, but still return all relevant RBs if possible

Recommended threshold for leaderboard quality:

either no hard cutoff in rows, but

only use players with something like 25+ rush attempts for percentile calculations

That avoids tiny-sample nonsense.
