Build a new WR Player Overview dataset for the WR explorer.

Goal

Create a JSON output for the WR Player Overview tab with pipeline-computed fields for role, opportunity, efficiency, stability, career context, and composite scores.

Output files

Create:

wr_player_overview.json
wr_player_overview_2023.json
wr_player_overview_2024.json
wr_player_overview_2025.json
wr_player_overview_all.json

Store them in the same output folder pattern as the QB and RB datasets.

Position filter

Only include WR players.

Field definitions
Identity
player: player display name
team: current/primary team abbreviation
age: current age
games: games played in sample window
snap_pct: offensive snap share percentage
Role & Usage
routes_per_gm: routes run per game
targets_per_gm: targets per game
receptions_per_gm: receptions per game
air_yards_per_gm: air yards per game
Opportunity
target_share_pct: target share percentage
air_yards_share_pct: air yards share percentage
wopr: weighted opportunity rating for WRs
rz_tgt: red-zone targets
Efficiency
catch_rate: catch rate
yards_per_route_run: receiving yards per route run
yards_per_target: receiving yards per target
yac_per_rec: yards after catch per reception
fpoe: fantasy points over expectation
Stability / Context / Composite
stability
volatility
career_arc
exp_tier
opp_score
usage_score
player_score
Data rules
use null only if data is truly unavailable
protect all rate stats from divide-by-zero
percentages should be stored as decimals, not formatted strings
example: 0.273
round numeric rate outputs to reasonable precision:
shares / catch rate: 4 decimals
wopr / yprr / yards per target / yac per rec / fpoe: 2 decimals
no duplicate players by canonical id
only WRs included
Default sort for backend output

Sort by:

player_score descending
opp_score descending
targets_per_gm descending
Validation

Before writing files:

all required fields exist
meta column order matches frontend expectation
no duplicate players
only WRs included
season/all variants write successfully
Important

Do not compute WR Tier in the backend JSON. That should be assembled client-side from existing fields after load.
